# Implementation decisions

The original choices below are retained as history. The current default is Qwen2.5 3B with explicit personal-life coverage; see [the scope update](personal-life-scope-update.md).

- **UI library choice:** No frontend dependencies existed. The standing `pick-ui-library` skill's curated React-oriented list does not cover a Python Streamlit demo; the approved specification explicitly proposes Streamlit, which supplies native chat, accessible labeled controls, feedback and session state. No React component or animation packages were added. UI/UX guidance prioritized a calm readable palette, generous spacing, standard widgets, visible labels and textual route cues alongside color. System fonts avoid external font requests.
- **LLM choice:** Qwen2.5 1.5B, Q4_K_M, through local Ollama on an 8 GB Apple M2 MacBook Air. It fits modest hardware and supports constrained JSON. It is a small general-purpose instruction model, not a clinically validated model. Temperature zero, seed 47309, context 2048, classifier max 24 generated tokens, support max 140 tokens. Prompts are versioned separately from the explicit policy. The model is replaceable via a Backend protocol. Exact weights and runtime metadata are in each run's config.
- **Delegate availability:** The requested OpenCode “GLM 5.2 Flash Free” model was not returned by the provider capability lookup. No alternative delegate model was used. Primary implementation, case authoring and automated evaluation stayed in this thread. This means held-out data and labels are not independently authored.
- **Contacts:** General local emergency/campus guidance is the allowed unknown-location branch. The empty external resource configuration avoids copying an unverified telephone number. A fail-closed resource validation helper is included for future integration; region selection and contact display are outside the current unknown-location demo.
- **Safety state:** A persistent boolean latch supplements the bounded context. History truncation cannot remove escalation. Only a fresh session clears it. Ambiguous safety questions set a follow-up flag; short affirmative danger replies receive deterministic escalation.
- **Privacy:** Only the evaluator writes dialogue artifacts, and it reads the checksum-verified fictional corpus. UI messages use plain text rendering; only static authored CSS uses HTML. No user-controlled markdown/HTML is rendered. CSV export escapes formula-leading strings. Error details are sanitized. No app-level conversation persistence or telemetry is configured.
- **Evaluation integrity:** Frozen dataset and approved-spec hashes are checked on every run; each run gets an exclusive new directory. Both final-dialogue confusion counts and all-turn critical checks are reported. Expected-routine latency cohorts include timeouts, fallbacks and misroutes so fast failures do not inflate successful-support timing. No clinical effectiveness inference is made.

- **Personal-life scope update:** Students are the target audience, not an academic-topic restriction. Revised support/classification prompts explicitly include personal concerns and avoid imposing study advice. The 150-case approved corpus stays unchanged; twenty extra personal-life cases are separately frozen as development coverage. See `docs/personal-life-scope-update.md`.
